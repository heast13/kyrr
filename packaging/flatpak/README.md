# Flatpak

The Flatpak of kyrr, written for a later submission to Flathub.

| File | What it is |
| --- | --- |
| `io.github.heast13.kyrr.yml` | The manifest: ONNX Runtime, sherpa-onnx (from source, without text-to-speech) and kyrr (from source, offline) |
| `cargo-sources.json` | Every crate in `Cargo.lock` as a download with its SHA256, generated by `flatpak-cargo-generator` |
| `flathub.json` | Builds on x86_64 only (see "Architectures") |

Desktop file, MetaInfo and icons are not copied here; the manifest installs
the shared ones from `packaging/linux/` and `crates/kyrr-app/ui/icons/`.

Runtime: `org.freedesktop.Platform` 26.08 with the SDK extensions
`rust-stable` (Rust 1.98) and `llvm22` (libclang for bindgen in
pipewire-sys). Update all three together when a new Freedesktop branch comes
out in August.

## Building locally

Needs `flatpak` and `flatpak-builder` (or the `org.flatpak.Builder` Flatpak),
about 6 GB for the runtime, SDK and extensions and about 6 GB for the build.

```sh
flatpak remote-add --user --if-not-exists flathub https://dl.flathub.org/repo/flathub.flatpakrepo
flatpak install --user flathub org.flatpak.Builder

# From the repository root. Build and repo folders outside the repository,
# or they would be copied into the build as part of the app source.
flatpak run --command=flathub-build org.flatpak.Builder --install packaging/flatpak/io.github.heast13.kyrr.yml
# or with a plain flatpak-builder:
flatpak-builder --user --force-clean --install-deps-from=flathub \
  --repo=$HOME/.cache/kyrr-flatpak/repo --install \
  $HOME/.cache/kyrr-flatpak/build packaging/flatpak/io.github.heast13.kyrr.yml

flatpak run io.github.heast13.kyrr
```

Check it the way Flathub does:

```sh
flatpak run --command=flatpak-builder-lint org.flatpak.Builder manifest packaging/flatpak/io.github.heast13.kyrr.yml
flatpak run --command=flatpak-builder-lint org.flatpak.Builder repo $HOME/.cache/kyrr-flatpak/repo
```

The app source is `type: dir` with `path: ../..`, the working tree as it is
(minus `target/`, `.git/`, `assets/` and flatpak-builder's own folders). The
noise models come from the manifest's own `file` sources, not from `assets/`.

### What the build does

1. **onnxruntime**: Microsoft's release archive, installed as
   `/app/lib/libonnxruntime.so.1` plus headers (headers are removed at the
   end by `cleanup`).
2. **sherpa-onnx** 1.13.8 from its git tag, CMake, static libraries,
   `SHERPA_ONNX_ENABLE_TTS=OFF` (no espeak-ng, no piper-phonemize) and
   speaker diarization off. Its CMake fetches dependencies with
   FetchContent, but looks for the archives in its source folder first and
   checks them against the same SHA256; the manifest puts them there as
   `file` sources (kaldi-native-fbank, kissfft, kaldi-decoder, kaldifst,
   openfst, eigen, simple-sentencepiece, nlohmann json). The environment
   variables `SHERPA_ONNXRUNTIME_INCLUDE_DIR` and `SHERPA_ONNXRUNTIME_LIB_DIR`
   make it use the ONNX Runtime above instead of downloading its own.
   Installed to `/app/sherpa-onnx`, which `cleanup` removes again: nothing of
   it ships except what is linked into `kyrr`.
3. **kyrr**: `cargo --offline build --release --locked -p kyrr` with
   `SHERPA_ONNX_LIB_DIR=/app/sherpa-onnx/lib`. sherpa-onnx-sys always links
   `espeak-ng`, `piper_phonemize`, `ucd` and `onnxruntime` as static
   libraries; the first three are empty archives as in
   `scripts/fetch-assets.py`, and so is `libonnxruntime.a`, because ONNX
   Runtime is the shared library here. `RUSTFLAGS` adds
   `-lonnxruntime` at the end of the link line, where the references from
   the sherpa-onnx archives resolve against `/app/lib/libonnxruntime.so`.
   Then the models go to `/app/share/kyrr` (`engine.rs` `assets_dir()`), the
   notices to `/app/share/doc/kyrr` (`platform.rs` `open_licenses()`, crate
   licenses through `scripts/collect-licenses.py`), and license files of all
   three modules to `/app/share/licenses/io.github.heast13.kyrr/`. ONNX
   Runtime's `LICENSE` and `ThirdPartyNotices.txt` also go to
   `/app/share/doc/kyrr/licenses/` as `LICENSE-onnxruntime.txt` and
   `ThirdPartyNotices-onnxruntime.txt`, the same names as in the AppImage and
   tarball (`scripts/package-linux.py`).

## Regenerating cargo-sources.json

After every change to `Cargo.lock`:

```sh
git clone https://github.com/flatpak/flatpak-builder-tools
python3 -m venv /tmp/fct && /tmp/fct/bin/pip install aiohttp tomlkit PyYAML
/tmp/fct/bin/python flatpak-builder-tools/cargo/flatpak-cargo-generator.py \
  Cargo.lock -o packaging/flatpak/cargo-sources.json
```

It lists every package in the lock file, the Windows-only ones included, so
it does not depend on the platform it runs on.

## Updating sherpa-onnx

`sherpa-onnx` is pinned in `crates/kyrr-dictate/Cargo.toml` (`=1.13.8`).
When it moves: change `tag` and `commit` of the sherpa-onnx git source, then
compare the `file` sources with the new tag's `cmake/kaldi-native-fbank.cmake`,
`kaldi-decoder.cmake`, `openfst.cmake`, `eigen.cmake`,
`simple-sentencepiece.cmake`, `json.cmake` and the nested ones
(`cmake/kissfft.cmake` of kaldi-native-fbank, `cmake/kaldifst.cmake` of
kaldi-decoder). `python3 cmake/download-all-deps.py` in the sherpa-onnx tree
lists them all. The file names (`dest-filename`) must be exactly the ones
the cmake files look for. Check `SHERPA_ONNX_STATIC_LIBS` in the new
`sherpa-onnx-sys` `build.rs` for libraries that need a stand-in, and the
ONNX Runtime version in `cmake/onnxruntime-linux-x86_64.cmake`.

## For the Flathub submission

1. Tag a release that has the Linux port and add it to the `<releases>` of
   `packaging/linux/io.github.heast13.kyrr.metainfo.xml` (Flathub shows the
   newest one; it must match what ships).
2. In the manifest, replace the `type: dir` source of the kyrr module with
   the commented-out `type: git` block: `url`, the release `tag` and its
   `commit` (`git rev-parse v0.X.Y^{commit}`).
3. Regenerate `cargo-sources.json` from that tag's `Cargo.lock`.
4. The pull request against `flathub/flathub` (branch `new-pr`) contains
   `io.github.heast13.kyrr.yml`, `cargo-sources.json` and `flathub.json`, side
   by side at the top level. Nothing else: no binaries, no copies of the
   desktop file or MetaInfo.
5. Run `flatpak-builder-lint` on the manifest and on the built repo first.
6. After the app is accepted, the ID `io.github.heast13.kyrr` can be
   verified on Flathub through the GitHub account `heast13`.

## Permissions

| Permission | Why |
| --- | --- |
| `--socket=wayland`, `--socket=fallback-x11`, `--share=ipc` | The window; X11 only without Wayland, IPC for X11 shared memory |
| `--device=dri` | OpenGL drawing (Slint's default renderer); without it Mesa draws on the CPU |
| `--share=network` | Speech model download on first dictation, "Check for updates" |
| `--filesystem=xdg-run/pipewire-0:ro` | The virtual microphone: a PipeWire source node and the default-source setting. As EasyEffects on Flathub. There is no portal for creating audio devices |
| `--socket=pulseaudio` | cpal records and plays through ALSA, and ALSA's default device in the Freedesktop runtime is the PulseAudio plugin (`/etc/alsa/conf.d/99-pulseaudio-default.conf`). Dictation, listening to yourself and the before/after test need it |
| `--talk-name=org.kde.StatusNotifierWatcher` | Tray icon |

Portals cover the rest without static permissions: GlobalShortcuts (the
push-to-talk key), RemoteDesktop (typing where the Wayland virtual keyboard
is not offered), Background, OpenURI (links and the license file).

## Open points for review

These need a decision or a code change before the submission; the manifest
alone cannot solve them.

### ONNX Runtime is a prebuilt binary

Flathub wants everything built from source. ONNX Runtime is the exception
here: the module uses Microsoft's official release archive
(`onnxruntime-linux-x64-1.28.2.tgz`, the version sherpa-onnx 1.13.8 is built
with). Other apps on Flathub do the same, for example `net.mkiol.SpeechNote`
(module `onnx`, Microsoft's 1.16.1 archive) and
`com.obsproject.Studio.Plugin.BackgroundRemoval` (Microsoft's 1.23.2
archive). `flathub/shared-modules` has no ONNX Runtime module. Reviewers may
still ask for a source build or grant it as a well-known-vendor exception.

Plan B, an `onnxruntime` source module that replaces the archive and still
installs `/app/lib/libonnxruntime.so.1` and the headers, so the other two
modules stay as they are:

- source: `type: git`, `https://github.com/microsoft/onnxruntime.git`, tag
  `v1.28.2` and its commit; `buildsystem: cmake-ninja`, `subdir: cmake`,
  `builddir: true`
- every entry of the tag's `cmake/deps.txt` that a CPU-only Linux build
  uses (abseil_cpp, date, eigen, flatbuffers, fp16, fxdiv, json,
  microsoft_gsl, mp11, onnx, protobuf, psimd, pthreadpool,
  pytorch_cpuinfo, re2, safeint, googlexnnpack/kleidiai only if enabled) as
  an `archive` source with `dest` set and
  `-DFETCHCONTENT_SOURCE_DIR_<NAME>=...` per dependency, plus
  `-DFETCHCONTENT_FULLY_DISCONNECTED=ON`; `protoc_linux_x64` is a prebuilt
  protoc, so protoc has to come from the protobuf source instead
  (`-DONNX_CUSTOM_PROTOC_EXECUTABLE=` or building protobuf first)
- flags: `-Donnxruntime_BUILD_SHARED_LIB=ON -Donnxruntime_BUILD_UNIT_TESTS=OFF
  -Donnxruntime_ENABLE_PYTHON=OFF -Donnxruntime_USE_XNNPACK=OFF
  -Donnxruntime_ENABLE_CPUINFO=ON -Donnxruntime_BUILD_BENCHMARKS=OFF
  -DCMAKE_BUILD_TYPE=Release`
- cost: a long C++ build (roughly an hour and several GB of RAM per job on
  Flathub's builders); set `-j` low enough or add
  `build-options: { cflags: -g1 }` if memory runs out.

### Tray icon: no well-known D-Bus name in the sandbox

Slint's tray (ksni 0.3) claims `org.kde.StatusNotifierItem-<pid>-<n>` on the
session bus. A Flatpak may only own names under its own ID, and Flathub's
linter rejects `--own-name=org.kde.*` without exception
(`finish-args-own-name-cpt`). ksni has `disable_dbus_name(true)` for exactly
this case; Slint does not use it. Until Slint does, or kyrr gets a tray of
its own on Linux, the app treats a Flatpak like a desktop without a tray:
the window minimizes instead of hiding, and closing it quits.
`--talk-name=org.kde.StatusNotifierWatcher` stays for when the tray works.

### Handled in the app

- Default microphone: PipeWire gives Flatpak clients read and execute only,
  unless they set `media.category = "Manager"` (as EasyEffects and Helvum
  do). `crates/kyrr-linux/src/mic.rs` connects that way, so the write to the
  `default` metadata works.
- Autostart: in a Flatpak, `platform.rs` asks the Background portal
  (`RequestBackground`, `autostart`, `["kyrr", "--background"]`) instead of
  writing `~/.config/autostart`, which the sandbox cannot reach.
- Second start: `$XDG_RUNTIME_DIR` is private to each running instance of a
  Flatpak; `crates/kyrr-linux/src/instance.rs` puts its socket in the shared
  `$XDG_RUNTIME_DIR/app/$FLATPAK_ID/` there, so
  `flatpak run io.github.heast13.kyrr --dictate` reaches the running kyrr.

### Typing on wlroots compositors

Sway, Hyprland and other wlroots compositors may hide privileged Wayland
protocols (virtual keyboard, data control) from clients that come with a
Flatpak security context. Then typing falls back to the RemoteDesktop portal,
which xdg-desktop-portal-wlr does not offer. Not testable here.

### Update check

Inside a Flatpak, updates come from Flatpak. "Check for updates" still works
(it only reads GitHub's latest release); on Linux there is no "Update now",
the note says to update where kyrr was installed from. Hiding the check when
`FLATPAK_ID` is set would avoid a reviewer question.

### PipeWire and PulseAudio permissions in app stores

GNOME Software and the Flathub website list `--filesystem=xdg-run/pipewire-0`
as file system access and may rate the app's permissions "potentially
unsafe";
`--socket=pulseaudio` shows as microphone and speaker access. Both are
needed for what the app does; the review comment should say so. Moving
dictation recording and playback from cpal's ALSA backend to its PipeWire
backend (cpal feature `pipewire`) would make `--socket=pulseaudio`
unnecessary.

### Slint license and `project_license`

`project_license` is `MIT OR Apache-2.0`, the license of kyrr's own source,
and Flathub asks that it match the license information in the source. That
holds. The binary links Slint, which kyrr uses under the Slint Royalty-free
Desktop, Mobile and Web Applications License 2.0 (Slint itself is
`GPL-3.0-only OR LicenseRef-Slint-Royalty-free-2.0 OR LicenseRef-Slint-Software-3.0`).
Flathub's guidelines do not ask to list licenses of linked libraries in
`project_license` (no app lists its whole dependency tree), so `MIT OR
Apache-2.0` is the expected value. If a reviewer wants the non-OSI component
visible, the expression would be
`(MIT OR Apache-2.0) AND LicenseRef-Slint-Royalty-free-2.0`, and GNOME
Software would then no longer show the app as free software. Two related
points:

- The royalty-free license requires attribution, either the "Made with Slint"
  badge on the page the app is downloaded from or the `AboutSlint` widget in
  the app. The Flathub app page is a download page without the badge;
  showing `AboutSlint` in kyrr's About section covers every channel.
- Distributing under Slint's GPLv3 option instead would put the combined
  binary under GPLv3 terms; that is not what the project chose.

### Architectures

x86_64 only (`flathub.json`): the native DPDFNet engine needs AVX2/FMA, and
on Linux kyrr does not hand ONNX Runtime to the denoiser, so an aarch64
build would have no noise filter. With `/app/lib/libonnxruntime.so.1` now in
the Flatpak, the denoiser's ONNX Runtime fallback could use it, which would
also cover x86_64 CPUs without AVX2.

### THIRD_PARTY.md

Its sherpa-onnx row says "the official static libraries ... statically
linked with ONNX Runtime". In the Flatpak, sherpa-onnx is built from source
(same version, same options apart from speaker diarization, which kyrr does
not use) and ONNX Runtime 1.28.2 is Microsoft's shared library next to it.
The notices are in the same place (`licenses/`), but the row describes the
other packages.
